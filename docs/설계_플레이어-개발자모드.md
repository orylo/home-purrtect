# 설계: 플레이어 모드 / 개발자 테스트 모드 분리

- **작성일**: 2026-06-01
- **상태**: 설계 확정 (구현 전)
- **목표**: 모바일 앱 출시를 향해, 순서대로 가는 **플레이어 모드**와, 직업·스테이지·난이도·스킬·아이템·재화·NPC를 자유롭게 테스트하는 **개발자 테스트 모드**를 분리한다. 시스템이 계속 늘어나도(상점·재화·NPC) 테스트가 쉽고, 출시 빌드엔 개발 요소가 안 보이게 한다.

---

## 1. 핵심 구조 — 3겹 + 출시 게이트

| 레이어 | 역할 | 사용 시점 |
|---|---|---|
| ① **런 설정 (run config)** — `GameState` | 이번 판의 모든 조건(직업/등급/스테이지/난이도/치트/재화…)을 담는 그릇. **게임 본체는 이것만 읽어 실행** | 항상 (backbone) |
| ② **개발자 메뉴** (시작 전 세팅) | 초기 조건 세팅 후 게임 진입 ("메이드 Lv3, 5스테이지, 어려움") | 진입 시 |
| ③ **인게임 디버그 오버레이** (플레이 중) | 버튼으로 패널 열어 도중 테스트: 코인 지급·상점 열기·NPC 소환·스킬/아이템 지급·스테이지 점프·무적·적즉사 | 플레이 도중 (핵심) |
| 🔒 **DEV 게이트** | 위 ②③ + 모든 치트를 단일 플래그로 묶음. 출시 빌드에선 자동 off → 흔적 없음 | 빌드 분기 |

**원칙**: 게임 본체(`main`/`player`/`spawner`)는 "누가 설정했는지" 모른다. 플레이어 모드든 개발자 모드든 **런 설정을 채우는 입구만 다르고, 실행은 동일**하다.

---

## 2. 진입 흐름

```
시작화면(start)
 ├─ [게임 시작]    → 저장 불러오기 → (해금된 직업만) 직업선택 → 게임  (플레이어 모드)
 └─ [개발자 모드]  → 개발자 메뉴 → 게임                              (DEV일 때만 버튼 표시)
```

- **플레이어 모드**: 해금 규칙 적용, 치트 없음, **진행 저장/이어하기**. 클리어 → 다음 스테이지 + 저장.
- **개발자 모드**: 자유 설정, 치트 가능, **저장 안 건드림**. 클리어/종료 → 개발자 메뉴로 복귀.

---

## 3. 컴포넌트 상세

### 3.1 GameState — 런 설정 + 저장
- **런 설정 필드(신규)**: `mode`("player"/"dev"), `difficulty`(난이도 배율 M), `cheats`{ `godmode`, `enemy_oneshot`, `enemy_count_mult` }, (기존) `selected_job`, `job_level`, `stage_major/minor`.
- **재화**: `coins`(나중 상점 시스템과 함께 채움. 지금은 필드만).
- **DEV 게이트**: `const DEV` 또는 `is_dev()` — 빌드 기능 태그(feature tag)로 결정. 출시 export 프리셋에선 `false`.
- **저장 시스템**: `user://save.json` (또는 ConfigFile).
  - 저장 내용: 클리어한 최고 스테이지, 해금 직업, (나중) 코인·보유직업·스킬.
  - `save()` / `load()` / `reset()`. **플레이어 모드만** 호출. 개발자 모드는 저장 파일 안 건드림.

### 3.2 시작화면(start)
- `[게임 시작]`(오렌지 CTA) + `DEV`일 때만 `[개발자 모드]`(작은 보조 버튼) 표시.
- 게임 시작 누르면 저장 로드 후 플레이어 모드 진입.

### 3.3 개발자 메뉴 (신규 씬 `dev_menu`)
- 직업 선택(4종) + **등급 슬라이더/버튼 Lv1~5**
- **스테이지 / 난이도(M)** 선택
- **치트 토글**: 무적 / 적 즉사 / 적 수 배율
- **스킬·아이템 슬롯** = 지금은 **빈 자리(placeholder)**, 시스템 생기면 연결
- `[이 설정으로 시작]` → 런 설정 채우고 game 진입(mode=dev)

### 3.4 게임 본체 (main/player/spawner)
- 시작 시 GameState 런 설정 적용:
  - player: 직업·등급(Lv 배율)·치트(무적 등)
  - spawner: 난이도 M(적 HP/수/속도 배율), 적 종류(나중)
- 클리어 시: player 모드 → 다음 스테이지 + 저장 / dev 모드 → 개발자 메뉴 복귀

### 3.5 인게임 디버그 오버레이 (신규, DEV 전용)
- 게임 화면 구석 작은 **🐞 버튼** → 누르면 패널.
- 패널 항목(시스템 생길 때마다 **버튼만 추가**해 확장):
  - 코인 +1000 / 무적 토글 / 적 전멸 / 적 즉사 토글
  - 스테이지 점프(다음/이전/특정)
  - (상점 생기면) 상점 열기 / (NPC 생기면) NPC 소환 / (스킬·아이템 생기면) 지급
- `DEV`가 아니면 버튼·패널 자체를 **생성 안 함**.

---

## 4. 출시 안전 (release gating)
- 개발자 메뉴 진입 버튼, 디버그 오버레이, 모든 치트 = **`GameState.DEV` 하나로 게이트**.
- `DEV`는 **export 기능 태그**로 결정: 개발 빌드 true / 출시 프리셋 false → 출시 빌드는 dev 코드가 **실행 자체가 안 됨**.
- 결과: "개발 빌드 = 디버그 풀세트 / 출시 빌드 = 완전히 깨끗".

---

## 5. 테스트 루프 (모바일 출시까지)
- **지금~중반**: 웹 빌드(GitHub Pages)로 폰 즉시 테스트 (현재 루프 유지).
- **출시 직전**: 네이티브 iOS 빌드 → TestFlight 실기기 베타.

---

## 6. 구현 순서 (한 단계씩)
1. **GameState 런 설정 + 저장/불러오기 + DEV 게이트** (backbone)
2. **시작화면 [개발자 모드] 버튼**(DEV 전용) + 0키 치트 정리
3. **게임 본체가 런 설정(난이도·치트) 읽게** 연결 (spawner 난이도 배율, player 무적/등급)
4. **개발자 메뉴 씬** (직업/등급/스테이지/난이도/치트 + 스킬·아이템 빈 슬롯)
5. **인게임 디버그 오버레이** (코인/무적/전멸/스테이지 점프 + 확장 자리)
6. **플레이어 모드 진행 저장/이어하기** 연결

## 7. 범위(YAGNI) 메모
- 스킬·아이템·상점·재화·NPC의 **실제 내용**은 이 설계 범위 밖. 여기선 **테스트 인프라(자리/훅)** 만 만든다. 각 시스템이 생기면 메뉴·오버레이에 버튼만 추가.
- 저장은 단순 JSON(스테이지/해금)부터. 클라우드 동기화 등은 후순위.
