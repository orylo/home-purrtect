# 공격 스프라이트 삽입 지침 (치즈 + 침입자 공통)

> **목적**: 새 공격 모션(스프라이트)을 넣을 때 **발사/타격 순간과 위치를 스프라이트와 정확히 맞춘다.**
> 이동·대기 등 다른 모션은 대충 넣어도 되지만, **공격 모션 — 특히 원거리 — 은 아래 프로세스를 반드시 따른다.**
> 주인=개발(Claude Code). 새 적/직업의 공격을 넣을 때마다 이 체크리스트대로 진행하고, 끝에 헤드리스로 검증한다.

---

## 핵심 원칙
1. **발사/타격은 "시간"이 아니라 "프레임"에 동기**한다. attack 애니의 실제 release 프레임에서 탄환이 나가거나 데미지가 들어가야 한다.
2. **원거리 탄환은 정확한 신체 부위에서 생성**한다(손·입·침·엉덩이 끝 등). 몸 중심이나 대충 위치 ❌.
3. 넣기 전에 **반드시 스프라이트를 눈으로 분석**한다(컨택트시트 + 중심/그리드 오버레이). 추측 ❌.
4. 넣은 뒤 **반드시 헤드리스 `--fixed-fps 60`로 검증**한다(발사 빈도=공격간격, 발사 위치, 데미지).

---

## A. 스프라이트 분석 (넣기 전)

### A-1. attack 프레임 컨택트시트로 "발사/타격 프레임" 찾기
- 모든 attack 프레임을 한 장에 모아 본다(어두운 적은 밝기 보정).
- **원거리**: 탄환이 **몸에서 분리되는 순간**(예: 손에서 돌이 사라지고 팔이 뻗음 / 침이 앞으로 / 입이 최대로 벌어짐 / 엉덩이 끝이 목표를 향함).
- **근접**: 부위가 **목표에 닿는 순간**(주먹·부리가 최대로 뻗음).
- 주의: 직관과 다를 수 있다. 끝까지(후반 프레임) 살펴라. (예: 거미는 #3이 아니라 **#9**에서 엉덩이가 완전히 좌측을 향함.)

```bash
# 컨택트시트(per=줄당 장수, bright=밝기). /tmp/<id>_atk.png 로 저장 후 Read로 확인.
python3 - <<'PY'
from PIL import Image, ImageDraw, ImageEnhance
import glob
ID="spider"; PER=8; TH=240; BRIGHT=1.8   # ← 적 id/값만 수정
fs=sorted(glob.glob(f"assets/sprites/enemies/{ID}/attack/attack_*.png"))
cells=[]
for i,f in enumerate(fs):
    im=Image.open(f).convert("RGBA"); w,h=im.size; sc=TH/h; im=im.resize((int(w*sc),TH))
    if BRIGHT!=1.0:
        r,g,b,a=im.split(); rgb=ImageEnhance.Brightness(Image.merge("RGB",(r,g,b))).enhance(BRIGHT)
        im=Image.merge("RGBA",(*rgb.split(),a))
    cells.append((i,im))
cw=max(c[1].width for c in cells)+8; rows=(len(cells)+PER-1)//PER
out=Image.new("RGBA",(cw*PER,(TH+18)*rows),(240,240,240,255)); dr=ImageDraw.Draw(out)
for i,(idx,im) in enumerate(cells):
    r=i//PER;c=i%PER;x=c*cw;y=r*(TH+18)
    out.paste(im,(x+4,y+16),im); dr.text((x+4,y+2),"#%d"%idx,fill=(200,0,0,255))
out.convert("RGB").save(f"/tmp/{ID}_atk.png"); print("saved /tmp/%s_atk.png"%ID)
PY
```

### A-2. 발사 프레임의 "발사 부위" 픽셀 위치 측정 (원거리만)
- 발사 프레임에 **중심 십자 + 40px 그리드**를 얹어, 발사 부위(손/입/침/엉덩이 끝)의 **프레임 중심 대비 픽셀 오프셋**(px=오른쪽+, py=아래+)을 읽는다.
- 적은 보통 **좌측(치즈 쪽)을 바라보므로** 발사 부위는 대개 **px 음수(좌측)**.

```bash
python3 - <<'PY'
from PIL import Image, ImageDraw, ImageEnhance
ID="spider"; FR=9; BRIGHT=1.5            # ← 적 id / 발사 프레임 번호
p=f"assets/sprites/enemies/{ID}/attack/attack_%02d.png"%FR
im=Image.open(p).convert("RGBA"); w,h=im.size
bg=Image.new("RGBA",(w,h),(235,235,235,255)); bg.alpha_composite(im)
r,g,b,a=bg.split(); bg=ImageEnhance.Brightness(Image.merge("RGB",(r,g,b))).enhance(BRIGHT).convert("RGBA")
dr=ImageDraw.Draw(bg); cx,cy=w//2,h//2
dr.line([(cx,0),(cx,h)],fill=(255,0,0,255),width=2); dr.line([(0,cy),(w,cy)],fill=(255,0,0,255),width=2)
for gx in range(0,w,40): dr.line([(gx,0),(gx,h)],fill=(0,150,255,110))
for gy in range(0,h,40): dr.line([(0,gy),(w,gy)],fill=(0,150,255,110))
bg.resize((w*2,h*2),Image.NEAREST).convert("RGB").save(f"/tmp/rel_{ID}.png")
print(f"{ID} #{FR}: frame {w}x{h}, center=({cx},{cy})  → 부위 픽셀에서 center를 빼면 오프셋")
PY
```
- **오프셋 = (부위픽셀 − center)**. 예: 거미 엉덩이 끝이 (81,180), center (196,150) → `Vector2(-115, +30)`.

## B. 코드에 반영 (`scripts/enemy_mouse.gd` — 침입자)

상수에 적 id를 추가한다:

| 상수 | 의미 | 넣는 값 |
|---|---|---|
| `ATK_RELEASE` | 발사/타격이 일어나는 attack 프레임 | A-1에서 찾은 프레임 번호 |
| `EMIT_OFFSET` | 발사 부위(프레임 중심 대비 px). **원거리만** | A-2에서 잰 `Vector2(px,py)` |
| `LOOP_SHOOTERS` | 사거리 안에서 계속 발사하는 지상/저공 원거리(투척쥐·거미·벌류) | id 추가 시 attack 네이티브 루프 + 속도=공격간격 자동 |
| `AIR_BOB` | 공중 유닛 상하진동(c=평균높이/a=진폭/s=속도) | 유닛마다 폭·속도 다르게 |
| `SIZE_MULT`/`FOOT_NUDGE` | 화면 크기/발 위치 보정 | 필요 시 |

동작 분기(이미 구현됨, id만 등록하면 자동 적용):
- **루프 슈터**(`LOOP_SHOOTERS`): 교전 중 attack 사이클을 네이티브 루프, `ATK_RELEASE` 프레임마다 `_fire_projectile()`.
- **공중 바닥트리거**(`AIR_BOB` 보유 + 비루프, 박쥐·참새류): 진동 최저점에서 1회 공격, release 프레임에 발사/타격. 박쥐처럼 "특정 높이에서만 공격"하면 최저점=그 높이로 `AIR_BOB.c/a` 설정.
- **일반 근접**(쥐 등): 트리거 시 attack 재생 → `ATK_RELEASE` 프레임(없으면 폴백 시간 `WINDUP_*`)에 데미지.
- **탄환 생성 위치**: `_emit_pos()`가 자동으로 `스프라이트중심 + EMIT_OFFSET×scale`(공중은 진동 높이 반영, flip_h 시 px 부호 반전). 새 적은 `EMIT_OFFSET`만 채우면 됨.

공중 적을 추가하면 **치즈 지상 근접 타격 높이**(`air_height_now()` ≤ `player.MELEE_AIR_REACH`)도 자동 연동된다 — 낮게 내려오면 점프 없이 맞음.

## C. 치즈(직업) 공격 스프라이트

치즈는 `scripts/player.gd`. 동일 원칙을 적용한다:
- **근접**: `melee_hit_delay`(또는 `_melee_pending`)를 **부위가 닿는 프레임**에 맞춘다.
- **원거리**: `ranged_fire_delay`를 **발사 프레임**에, `muzzle_offset`을 **발사 부위(손/총구)** 픽셀 위치(스케일 반영)로 맞춘다. 직업마다 다르면 직업별로.
- 측정은 위 A-1/A-2 동일(경로만 `assets/sprites/cheese/<직업>/`).

## D. 검증 (반드시)

```bash
G=/Applications/Godot.app/Contents/MacOS/Godot
"$G" --headless --check-only --script scripts/enemy_mouse.gd   # 구문
# 발사 위치/빈도/데미지: --fixed-fps 60 로(헤드리스 기본은 wall-clock이라 애니가 느려 부정확)
```
- **발사 위치**: `e._emit_pos() - e.global_position` 가 의도한 부위인지.
- **발사 빈도**: 8초간 발사수 ≈ `8 / atkint` (루프 슈터·공중 진동 주기).
- **데미지**: 실제 플레이어/더미 상대로 health 감소 확인.
- 최종 픽셀 정합은 **사용자 F5**로 눈 확인(수치 미세조정).

---

## E. 핵심 함정
- 헤드리스 기본 실행은 프레임 delta가 wall-clock이라 애니가 느려 **발사 횟수가 적게 나온다 → 반드시 `--fixed-fps 60`**.
- `play("attack")`가 **마지막 프레임에서 안 되돌아감** → 루프는 SpriteFrames 복제 후 `set_animation_loop("attack",true)`(공유 리소스 보호).
- 발사 프레임은 **직관과 다를 수 있다**(거미 사례). 끝까지 보고, "탄환이 몸에서 떨어지는" 바로 그 프레임을 고른다.
