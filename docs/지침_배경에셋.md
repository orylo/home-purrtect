# 지침 — 배경 에셋 제작 (풀블리드 · height-fit)

> **이 문서의 역할:** 스테이지 배경(원경/중경/지면)을 어떤 크기·구도로 그릴지 고정. 그래픽 작업 시 먼저 읽기.
> **결정(2026-06-04):** 풀블리드(검은 띠 0) + **height-fit**("상하 꽉 고정, 좌우는 기기 따라 잘림/확장"). 세로 구도는 전 기기 동일, 가로 길이만 기기별로 다름.
> **⚠️ 코드 상태:** 현재 코드는 아직 `expand`+cover-fill(옛 16:9 배경 기준). **실제 21:9 그림 1장 나오면** 그 그림에 맞춰 코드를 height-fit/앵커로 전환·검증한다(추측으로 먼저 안 바꿈). 그림 → 코드 순서.

---

## 1. 캔버스 크기 = **2520 × 1080 px** (21:9)
- 2520 ÷ 1080 = 2.333 = 21:9 (지원할 가장 넓은 폰 기준).
- 또렷하게: 2배(5040×2160)로 그린 뒤 export 시 축소도 OK. 웹 용량 고려하면 2520 기준 권장.
- **원경/중경/지면 전부 같은 2520×1080 캔버스**(정렬 일치). 중경·지면은 투명 PNG.

## 2. 세로(높이) = 전 기기 100% 보임 → 구도를 여기에 꽉
- 하늘 맨 위 ~ 지면 맨 아래까지 풀로. 위아래 안 잘림.
- **HUD 가림 주의**: 상단 ~80px(체력바·정보) / 하단 ~120px(조작 버튼)에는 **핵심 디테일(저택 꼭대기 등) 두지 말 것.**

## 3. 가로(폭) = 가운데 안전, 양옆 여백 (3단 세이프존)
```
2520 × 1080
| 여백 |  폰존  |   절대안전(4:3)   |  폰존  | 여백 |
 0~540   16:9     가운데 1440        16:9   1980~
                  (x 540~1980)              2520
```
| 영역 | x 픽셀 범위 | 폭 | 넣을 것 |
|---|---|---|---|
| **절대안전** (가운데 4:3) | **540 ~ 1980** | 1440 | 태블릿(아이패드)까지 보이는 **핵심**(중심 오브젝트) |
| **폰존** (가운데 16:9) | 300 ~ 2220 | 1920 | 일반 구도(거의 모든 폰서 보임) |
| **여백** (21:9 전체) | 0 ~ 2520 | 2520 | 광폭폰만 봄 — 풀숲·담장 연장·하늘 (잘려도 OK) |

- 핵심일수록 안쪽(절대안전 1440) → 바깥(여백)으로 갈수록 "잘려도 되는" 장식.

## 4. 수평선 · 바닥선
- 캐릭터 발(게임 바닥선)이 화면 아래 약 **30~35%** 지점. → 배경의 **"지면이 시작되는 경계선 y"**를 거기에 맞춤.
- 지면 PNG는 "땅 윗선(표면)이 전체 높이의 몇 %인지"만 알려주면 코드(`GROUND_SURF`)에 등록해 발선과 정렬.

## 5. 기기별로 어떻게 보이나 (참고)
| 기기 | 가로 플레이 폭 | 배경 |
|---|---|---|
| 21:9 폰 | 길다 (캔버스 전체) | 2520 다 보임 |
| 19.5:9 폰(기준) | 중간 | 가운데 ~상당부분 |
| 16:9 | 짧아짐 | 가운데 1920권 |
| 아이패드 4:3 | 개짧음 | 가운데 1440권 |
- **세로 구도는 어디서나 동일**(저택 항상 다 보임), 좌우 길이만 다름. 좁은 기기는 스테이지가 짧아 약간 더 빡셈(난이도 차이 감수).

---

## 작업 순서
1. (이 문서) 스펙 확정 ✅
2. **당신**: 1-1 원경 1장 테스트로 2520×1080 제작.
3. **Code**: 그 실제 그림으로 코드 height-fit/앵커 전환 + 폰/PC/아이패드 비율 스크린샷 검증.
4. OK → 나머지 스테이지 배경 제작, 같은 방식 적용.
